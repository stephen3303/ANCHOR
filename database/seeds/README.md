# Bundled seed data

`PLADS.txt` is the command directory supplied for this project, originally moved
from `~/Downloads/PLADS.txt`. Its header says **Updated 04 Nov 2026**. The file is
bundled with the repository so a new checkout needs no external Downloads file.
It contains 29,970 unique command names after removing its header and blank lines.

After starting PostgreSQL and applying schema migrations, import it with:

```sh
npm run db:seed:commands
```

The importer defaults to this file and retains existing command IDs on reruns.
An explicit alternative path is still supported:

```sh
npm run db:seed:commands -- /path/to/PLADS.txt
```

Run the import during first-time setup or when refreshing the source—not on
ordinary database startup. Replace this file deliberately when updating the
directory, review the diff, then rerun the import. The importer adds missing
names; it does not remove old entries or update existing names.

## Standard Message

`standard-message.json` snapshots the project's authored **Standard Message**
plaintext and input controls: precedence codes, autogenerated sender command,
newline-separated TO/INFO pickers and the remaining required text fields. The
existing header TODO and manual date/time/message-number fields are preserved.
Body is a multiline textarea. The corresponding frozen migration 006 seed has
been amended for fresh databases; migration 008 creates a new textarea version
for existing Standard Message definitions without changing old versions/pins.
The migration runner audits the one allowed 006 checksum transition; it does not
ignore other applied-file checksum mismatches.

Migration `006-standard-message-template.sql` includes a frozen, compiled copy,
so fresh databases receive published version 1 automatically. It creates its
normal LTaylor demo creator only if needed and never overwrites existing users
or matching templates. `npm run db:seed:templates` is an optional idempotent seed
command using the same application validator/compiler. Matching by the stable
`standard-message` key or case-insensitive name also recognizes the original
UI-created template without duplicating it, rewriting its UUID or republishing
its versions. Archived templates stay archived. No messages are created by seeding.

Changes to the JSON do not alter published versions. Publish a new version
explicitly; do not regenerate/edit an already-applied SQL migration.
`npm run test:templates:seed` checks both the script and the automatic migration
against an isolated disposable database.

This folder holds **source data only**. Live PostgreSQL data remains in the
`postgres_data` Docker volume. No live database files were moved or reset.
See [`database/README.md`](../README.md) for setup versus routine startup.
