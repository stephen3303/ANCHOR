# Bundled seed data

`PLADS.txt` is the command directory supplied for this project, originally moved
from `~/Downloads/PLADS.txt`. Its header says **Updated 04 Nov 2026**. The file is
bundled with the repository so a new checkout needs no external Downloads file.
It contains 29,970 unique command names after removing its header and blank lines.

After starting PostgreSQL and applying schema migrations, import it with:

```sh
npm run db:seed:commands
```

The importer defaults to this file and retains existing command IDs on reruns.
An explicit alternative path is still supported:

```sh
npm run db:seed:commands -- /path/to/PLADS.txt
```

Run the import during first-time setup or when refreshing the source—not on
ordinary database startup. Replace this file deliberately when updating the
directory, review the diff, then rerun the import. The importer adds missing
names; it does not remove old entries or update existing names.

## Standard Message template

`standard-message.json` is a snapshot of the project's UI-authored **Standard
Message** template, including its plaintext, required fields, precedence output
codes, server-generated sender command, and newline-separated TO/INFO command
pickers. The existing header TODO and manual date/time/message-number inputs are
preserved as authored; this seed does not redesign the message format.

After migrations and `npm run db:seed:users`, run:

```sh
npm run db:seed:templates
```

The seed validates and compiles the definition using the application's template
compiler and publishes version 1, attributed to the seeded `LTaylor` account.
Autogenerated values remain bindings and are resolved when a message is saved,
not while seeding. No messages or drafts are created by this command.

Reruns do not overwrite or duplicate an existing template identified by the
stable `standard-message` key or the name `Standard Message` (case-insensitive).
Existing definitions, IDs, published versions, pending edits and archived state
are preserved. To change an already-published template, deliberately create a new
version rather than expecting a seed rerun to modify it.

`npm run test:templates:seed` checks first-time seeding and preservation against
an isolated database, which it removes when finished.

This folder holds **source data only**. Live PostgreSQL data remains in the
`postgres_data` Docker volume. No live database files were moved or reset.
See [`database/README.md`](../README.md) for setup versus routine startup.
